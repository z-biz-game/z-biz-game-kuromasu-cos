# 黑目 · Kuromasu（零猜测黑目推理）

> *数字不告诉你哪一格是黑的，只告诉你这条十字视线里数得着几个白格。每一局出货前都被铅笔路径从空盘推到底过一次，唯一解由第二套互不信任的代码逐格复核。*

浏览器原生的 **Kuromasu / 黑目（Kurodoko）**：无构建步骤、无打包器、**零美术与音频文件**——
纸面、墨块、视线环全部由 canvas 现画，音效由 WebAudio 合成，界面只有一个 `<canvas>`。

玩法是**把每一格定成黑或白**：格子上的数字写着「从这个数字出发，四条视线在第一个黑格之前
一共能看见几格白（含它自己）」；黑格不许上下左右相接；所有白格必须连成一片。

- **核心承诺 1｜零猜测**：出货的每一局都能 **只用下面那五条规则从空盘推到底**。这不是文案，是准入门槛——
  `pruneClues` 每删掉一个数字都要重跑一遍铅笔路径，推不到底的删法当场回滚（`js/engine/generate.js:89`）。
- **核心承诺 2｜唯一解**：`countSolutions()` 是一台**不含任何推理规则**的逐格穷举计数器
  （`js/engine/count.js` 自己重新推了一遍视线几何，状态用位掩码带，跟 `kuromasu.js` 只共享四个常量）。
  它和铅笔路径从两个方向回答同一个问题，还要**逐格**给出同一份黑白，否则不出货。
- **核心承诺 3｜提示不是答案**：提示走的是**同一个** `solve()` 产出的推导脚本，所以它必须点名
  用了哪条规则、落在哪一格（`R3C2 写着 4，视线里已经看见 3 格白了，R3C4 再留白就多一格——所以那格必须是黑格`）；
  玩家自己的墨已经和数字矛盾时，提示**拒绝落子也不收费**，只说出这里为什么矛盾。
- **核心承诺 4｜死局会被提前说出来**：涂错一格常常**不违反任何一个数字**——视线还长，数得过来。
  `reachable()` 把玩家的墨当成前提跑一遍那五条规则，一旦逼出矛盾就说
  「不管剩下的格怎么放，都不可能让所有数字对上」。这条判据只在真矛盾时开口（见 DESIGN §7）。
- 难度不是标签：`初学 → 大师` 五档的分数带是**实测**出来的（`npm run balance` 打印分位表），
  档位排的是「盘面多大」×「留下多少数字」，`band` 是**选取目标**，`balance` 盯着不许漂移。
- 规模：10 个 ES Module / 2,667 行 JS + 7 个验证脚本 / 3,102 行 + 629 行 CSS/HTML，**运行时依赖 0 个**。
- 验证：**214 项 Node 断言** + **410 项浏览器断言**（10 个场景，读 DOM 几何与画布像素，不读标志位）。
- **在线试玩**：<https://z-biz-game.github.io/z-biz-game-kuromasu-cos/>（`main` 分支推送即自动部署）

```bash
npm start            # 零依赖静态服务 → http://127.0.0.1:5254
npm run dev          # 本项目专用端口 5254（验证脚本用同一个）
npm run electron     # 桌面壳（electron/main.cjs，同一份代码）
```

```bash
npm run check        # 逐文件 node --check 语法门禁
npm test             # 引擎断言 214 项：规则可靠性 / 生成保证 / 状态机 / 存档形状
npm run balance      # 难度实测台：每档分数分位、命中率、求解代价、档位阶梯门禁
npm run doctest      # 文档等式：README / DESIGN 印出的每个现值都对代码重算一遍（只比现值，不复测耗时）
npm run sabotage     # 破坏台账：四把刀各写一类谎进临时副本，文档闸必须点名变红（见下）
```

那 10 个场景的**逐行**条数钉在 `tools/verify.sh` 的 EXPECTS 表里（上面那段输出抄的就是这张表，改一条断言就得同时改两
case）：一个场景少一条、另一个多一条而总和不动，光看总和是分辨不出来的。

`gen` 那两列负数对照组是**故意**的：门控之后再多删一个数字必须造出多解盘（12 盘里 8 盘不再是唯一解），

同一套断言可以直接打线上产物，"部署过没部署过"不是一句声明：

```bash

```

## 破坏试验台账（这把闸会不会红）

`npm run doctest` 报全绿只说明「这一轮文档没漂」，它没说**这把闸会不会红**——一把从没红过的闸和一把
没接线的闸，输出是一模一样的。所以台账进树：`npm run sabotage` 内置四把刀，每把在**工作区根的临时副本**
里做一个最小扰动，跑文档闸，断言必须看到**预期的那一条 FAIL 行**（连明细一起对）；任何一把没红或没点名
就整体判红并报出自己的 id。CI 的 check job 与 `tools/verify.sh` 的 logic 档跑的是同一个脚本，本地没有
「只有 CI 才有的门」，CI 也没有只在那边才关得上的门。刀不碰仓里的真文件，所以不需要 `git checkout`
去擦自己留下的痕迹（共享工作里那会把别人正在写的东西抹掉）；副本跑完即删，日志留在工作区根的
`_tmp-kuromasu-sab-*.log`。

| 刀 | 打在哪一侧 | 这一把做的最小扰动 | 必须点名的 FAIL |
|---|---|---|---|
| S1 | 文档 | README 档位表 大师 那一行把 `28%` 印成 `30%` | `D1c 大师 留 28%` · `文档 30% vs 代码 28%` |
| S2 | 文档 | README 规则表 白不断路 那一行把 `2.5` 印成 `3`（DESIGN 不动） | `D2c 白不断路 的权重 2.5` · `README 3 /` |
| S3 | 代码 | `Rules.island` 的权重 `2.5` 改成 `3`（两张表都留在 2.5） | `D2c 白不断路 的权重 3` · `README 2.5` |
| S4 | 代码 | generate 的默认抽盘次数 `24` 改成 `25`（DESIGN 没跟） | `D6g` 的 tries · `文档 24 vs 代码 25` |

S2 与 S3 是同一条断言的两侧：只盯标签里的数分不出漂移在哪一边，所以两把刀各配一条明细——文档那侧的
明细是 `README 3`，代码那侧是 `README 2.5`（跟着动的换成代码）。台账另带两个反空转：**不带刀的副本**
必须先全绿（否则「红是复制这件事造出来的」排不掉，四把刀的红就都不作数）；跑完再验一次工作树仍然干净。

## 玩法

| 操作 | 行为 |
|---|---|
| **拖动** | 沿路把经过的格定成当前这笔的墨；一笔算一步，数字那一格被跳过（并说明为什么） |
| **从已定的格里起笔** | 整笔变成橡皮——同一种墨再点同一格就是擦掉 |
| **`B` / `W`**（或 `M` 换笔） | 选墨：■ 涂黑 / □ 留白；`E` 或**右键**开橡皮，右键不改当前画笔 |
| **提示**（或 `H`） | 给出当前推得出的一格，并点名规则；这一步真的落子，也真的计入求助次数 |
| **撤销**（或 `Z`） | 退掉一整个手势——一笔拖过的格子一起回来；**提示次数不退** |
| **暂停**（`P` 或空格，HUD 上那颗 `#btn-pause`） | 时钟定格：`dt` 不再进仿真，恢复时不补一个尖峰 |
| **全屏**（`F`，HUD 上那颗 `#btn-fullscreen`） | 元素级全屏；浏览器不提供时那颗按钮置灰并把原因写进 `title`（iOS Safari 走"添加到主屏幕"） |
| **静音**（`N`，HUD 上那颗 `#btn-sound`） | 这颗键只把按键翻译成"点一下音效按钮"：真静音在 `js/audio/synth.js` 里——`suspend()` 掉 `AudioContext` 且静音态不再新建振荡器节点，偏好落盘 |
| **重开本题**（`R`，HUD 上那颗 `#btn-restart`） | **同一道题**原地重来：笔迹、撤销栈、步数、提示次数、提示游标、计时、结算遮罩全归零，题面与盘号不变。跟「换一局」的分工是明确的——换一局重抽一道新题，这颗是"这题我走错了"。归零清单见 `Game.resetAll()`：只调引擎的 `resetInk()` 会漏掉 UI 层那几样，实测 `steps 6→6`、`cursor 40→40` |

玩法那六颗键（`B` `W` `M` `E` `H` `Z`）的护栏是"焦点在 `input`/`textarea` 里不触发"；
`P` `F` `N` `R` 这四颗把 `select` 也算进输入态，并且一律忽略 `meta`/`ctrl`/`alt`。
文档操作表里出现的字母键与 `js/main.js` 真处理的按键由 D11 钉成一一对应——谁单方面多一颗少一颗都红。

判胜用的是 `verify()`：只读盘面，按游戏本来的四条事实判——没有待定格、每个数字数得对、
黑格不相邻、白格连成一片。它不读推导脚本，所以**提示逻辑写错也伪造不出一场胜利**。

同档纪录先比求助次数，再比用时（`js/main.js:209`），所以「一路提示到底」不会变成捷径。

## 五条规则（提示只会说这些）

| 规则 | 说什么 | 权重 |
|---|---|---|
| 带字即白 | 写着数字的那一格必须是白格——黑格上不写字 | 1 |
| 黑不挨黑 | 黑格的上下左右都不许再是黑格 | 1 |
| 已经看满 | 视线里白格已经数够 → 还没定的那一格必须涂黑 | 1.5 |
| 非看不可 | 四条视线全打开也刚好只有这些 → 那几格必须留着白 | 2 |
| 白不断路 | 一涂黑就把白格劈成两截的那一格，必须是白格 | 2.5 |

前四条里，每条都只数**一条视线或一个黑格自己的账**；最后一条看整块盘。写下的每一格
在盘面的**每一个解**里都成立——这就是"零猜测"得以成立的原因，也是 `reachable()` 敢开口的原因。

## 屏上的每个颜色是谁算出来的

| 屏上 | 出处 | 不是谁 |
|---|---|---|
| 数字画成红圈 | `board.clueBad` = 引擎 `diagnose().violated` 里**写着数字**的那些格 | 不是渲染层自己数了视线 |
| 数字画成绿圈 | `board.clueGood` = 同一个 `violated` 的补集，同样限制到数字格 | 不是"这一格我猜是对的" |
| 没数字的格描一圈 | `board.otherBad` = `violated` 里**不写数字**的格（黑挨黑、白被劈开） | 不是第二次判定 |
| 已定 / 看对 / 冲突 三个读数 | `Game.state()` 直接取自 `diag`、`clueGood`、`violated` | 不是面板自己累加 |

`layout` 场景从像素侧钉住这张表：沿数字环采 12 个点，要求至少 4 个落在 `--error` / `--success` 上，
并且**同一局里绿环与红环不可能同时命中**（`tools/scenarios.js` 的 `ringCount`）。

## 难度是量出来的

`npm run balance`（SAMPLES=40，2026-09-27）：

| 档 | 盘面 | 留多少数字 | 分数带（选取目标） | 实测中位 | 命中区间 | 平均抽几次 | 出题耗时 |
|---|---|---|---|---|---|---|---|
| 初学 | 5×5 | 50% | 31–37 | 33.5 | 40/40 | 1.1 | 0.6 ms |
| 上手 | 6×6 | 42% | 45–54 | 50.0 | 40/40 | 1.1 | 1.3 ms |
| 熟练 | 7×7 | 38% | 64–73 | 69.5 | 40/40 | 1.1 | 1.8 ms |
| 高阶 | 8×8 | 34% | 85–99 | 91.0 | 40/40 | 1.1 | 3.2 ms |
| 大师 | 10×10 | 28%（黑格 32%） | 130–148 | 142.0 | 40/40 | 1.3 | 12.9 ms |

出题耗时那一列是**同一次运行的实测值**，它会随机器负载浮动（同一份代码两次跑，10×10 在
12.7–12.9 ms 之间跳过）——所以它是观察量，不是断言：`balance.mjs` 对耗时没有任何预算，
它只对「命中区间」「推不出来的盘 = 0」「超预算未核 = 0」这些真正会红的项目下结论。

五档「推不出来的盘」都是 0，穷举复核 16/16 与铅笔判定一致且**超预算未核 0 局**，
同一块盘重跑同分 5/5，出题器种下的解 60/60 通过独立验收。
分数是**推理步数按上表权重加权**的和，所以它同时反映盘有多大、数字有多稀；
`推理步数` 那一列恒等于格子数（一条提示写一格），它**不**衡量难度，所以档位不用它。

